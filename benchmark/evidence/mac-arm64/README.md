## 公平性

- 两版都由 `benchmark/run-suite.sh` 驱动，每轮前执行同一个 `reset-env.sh`。
- unique：75/s × 60s，库存 1000。
- duplicate：75/s × 60s，库存 1000，1000 个用户循环。
- selltail：300/s × 30s，库存 100。
- 三轮中位数按“每个指标分别排序取中间值”计算，因此不存在一个文件能同时代表所有指标的中位数。

## 文件选择说明

- 主场景稳定文件按“成功入队 p95 接近三轮中位数且 verify 可读”选择代表轮次。
- `runs/` 保存基线/优化后三场景共 18 个 summary、async-off 3 个 summary，以及 3 个真实异常轮次 verify；公开仓库无需依赖被忽略的 `benchmark/results/` 即可重算中位数并核查异常。
- `baseline-all-on-*` 与 `optimized-all-on-*` 是限流、anti-brush、动态限流、隐藏 path 全开的单轮对照。
- `async-on-*` 使用优化版主场景代表轮次；`async-off-*` 使用相同 jar 关闭异步日志后的代表轮次。
- `*-db-metrics.txt` 同时包含压测前、压测后计数。采样窗口约 20 分钟，包含 60 秒压测、等待最终对账和后台任务；目标 SQL digest 可用于 D2/D3 归因，`Com_select` 只视为同长度观测窗口总量。

## 正确性解释

MySQL 分段库存开启时，`sku_stock_segment` 是扣减事实，`sku_stock` 是由定时对账同步的汇总视图；若采样撞上同步窗口，汇总视图可能暂时滞后。验收同时核对成功订单、分段库存合计、重复订单组、消息状态和 RabbitMQ 队列。
