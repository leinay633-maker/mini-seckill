# 竞品参考

本文件记录 GitHub 上类似秒杀项目的可借鉴点。这里的参考只用于设计对比和面试表述，不表示本项目复制了第三方代码。后续如果真的引入第三方代码，必须先确认许可证，并在本文件补充来源和版权说明。

## 参考原则

1. 只把公开项目当成架构和功能清单参考，不能把别人的压测数字写成本项目指标。
2. 许可证不清的仓库，只能学习思路，不能复制代码。
3. 参考点要落回本项目源码或文档：已经实现就写“已实现”，没有实现就写“后续优化”。
4. 面试时重点讲自己的验证链路：`REPORT.md`、`benchmark/evidence/mac-arm64/`、源码和 SQL。

## zaiyunduan123/springboot-seckill

地址：`https://github.com/zaiyunduan123/springboot-seckill`

可参考点：

- 页面缓存、对象缓存、页面静态化。
- 本地标记 + Redis 预处理 + RabbitMQ 异步下单 + 客户端轮询。
- 库存更新时加条件判断，用户和商品维度做唯一约束，避免重复秒杀。
- 数学验证码和 RateLimiter 限流。

本项目对应情况：

- 已实现类似的本地售罄标记、Redis 预扣库存、RabbitMQ 异步削峰、订单查询状态、用户 SKU 幂等和 MySQL 条件扣库存。
- 本项目没有页面层，不做页面缓存和静态化。
- 本项目已经补了服务端短 TTL 隐藏下单 path 和可选数学验证码，但还没有图片/滑块验证码和网关层风控校验，这是后续可补点。
- 本项目比普通 demo 多了本地消息表、confirm/return、重试、回放、Redis 恢复和对账补偿。

## hfbin/Seckill

地址：`https://github.com/hfbin/Seckill`

可参考点：

- Spring Boot + MyBatis + Redis + RabbitMQ 秒杀系统。
- V2.0 分支强调页面缓存、商品详情静态化、订单静态化、RabbitMQ 优化、隐藏秒杀接口地址、接口限流防刷和超卖控制。
- 项目提供登录页、商品列表、订单详情等完整演示页面。

本项目对应情况：

- 技术栈接近，但 MiniSeckill 更偏后端链路和面试证据，不做前端页面。
- 已实现 Redis、RabbitMQ、MyBatis、库存防超卖和重复订单约束。
- 隐藏秒杀接口地址、demo JWT 和可选数学验证码已有服务端骨架；真实用户中心、图片/滑块验证码和网关层校验仍可作为后续功能增强。

## halegreen/spring-boot-seckill

地址：`https://github.com/halegreen/spring-boot-seckill`

可参考点：

- 强调分流、限流、缓存、异步和主备。
- 讨论 Nginx、SLB、静态资源、数据库连接池、分布式锁、消息队列和全链路压测。
- 更像“完整秒杀架构讲解 + 案例代码”，适合参考分层优化思路。

本项目对应情况：

- 已有 Nginx 示例、多实例 compose 示例、Redis Cluster 演示、动态限流、缓存预热、RabbitMQ 异步和压测脚本。
- 没有真实云上 SLB、多机部署、全链路监控平台和主备容灾。
- 面试时可以说“我参考了行业常见的分流、限流、缓存、异步思路，但用本项目的报告数字证明边界”。

## Grootzz/dis-seckill

地址：`https://github.com/Grootzz/dis-seckill`

可参考点：

- 模块化拆分为 user、goods、order、gateway、cache、mq 等服务。
- 通过 Gateway 承接用户请求，再调用后端服务。
- TODO 中提到 JWT、服务横向扩展、网关扩展、Nginx 水平扩展和接口压测。

本项目对应情况：

- MiniSeckill 当前是单体服务，适合面试展示一条主链路，不刻意拆微服务。
- 已经补了 demo JWT、多实例、Nginx compose 和监控 compose；后续生产化可继续向网关、微服务和真实压测演进。
- 对比时不要把“微服务模块化”说成已实现，只能说“后续生产化可以拆”。

## 综合结论

常见开源秒杀项目通常覆盖这些点：

- 登录或用户体系。
- 页面缓存、页面静态化、静态资源前置。
- 验证码、隐藏秒杀地址、限流防刷。
- Redis 预扣库存。
- RabbitMQ 或 Kafka 异步下单。
- 防超卖、防重复。
- Nginx 或网关分流。
- Swagger/OpenAPI 接口文档。
- Prometheus/Grafana 可观测性配置。

MiniSeckill 当前更适合突出这些差异：

- 有单机真实压测报告和原始结果文件，不只停留在 README 设计。
- 有本地消息表和 RabbitMQ confirm/return 状态机。
- 有消息重试、DEAD 回放、排队超时和补偿记录。
- 有 Redis 宕机 fail-closed、恢复公式和恢复后对账证据。
- 有 MySQL 分段库存和 Redis 分桶库存，能解释热点拆分。
- 有 demo JWT、可选数学验证码、Swagger、Nginx compose 和 Prometheus/Grafana provisioning，能补齐常见 GitHub demo 的展示缺口。
- 边界写得比较清楚，不把 10 万并发方向说成已经实测。
